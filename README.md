# Phishing Simulation & Security Awareness Test

An internal tool for running **authorised phishing simulations** for employee
security-awareness training. You send a mock phishing email to your own staff;
when someone clicks the link, the click is recorded in Supabase and the person
lands on a page that teaches them how to spot phishing attacks.

> ⚠️ **Authorised use only.** This is a defensive training tool intended to be run against your own organisation's staff, with management approval. It is not for targeting anyone outside your organisation.

Built with [Next.js](https://nextjs.org) (App Router) + [Supabase](https://supabase.com),
styled with [Tailwind CSS](https://tailwindcss.com) and [shadcn/ui](https://ui.shadcn.com/).

## How it works

1. **Send the bait email.** You compose a simulated phishing email (e.g. in
   Gmail) that looks like a real message, containing a tracking link such as:

   ```
   https://rila-notifications.vercel.app/test?template_id=1&email=duyen@rilaglobal.com
   ```

   - `template_id` — which email template / campaign this click belongs to.
   - `email` — the recipient the link was sent to, so you know who clicked.

2. **Recipient clicks the link.** They land on the `/test` page
   (`app/test/page.tsx`).

3. **The click is recorded.** On load, the page reads `template_id` and `email`
   from the query string and calls Supabase:
   - If a row for that `(template_id, email)` pair already exists, it increments
     `number_of_click` and updates `latest_timestamp`.
   - Otherwise it inserts a new row with `number_of_click = 1`.

4. **The recipient is educated.** The `/test` page renders
   `components/cyber.tsx`, explaining that this was an authorised simulation and
   how to identify phishing in future — no harm done.

5. **You review results** in the Supabase `phishing_test` table to see who
   clicked and how often.

## Supabase setup

The app needs a Supabase project with a `phishing_test` table. Create it in the
Supabase SQL editor:

```sql
create table public.phishing_test (
  id               bigint generated by default as identity primary key,
  template_id      bigint not null,
  email            text   not null,
  number_of_click  integer not null default 1,
  latest_timestamp timestamptz default now(),
  created_at       timestamptz default now()
);
```

Click tracking happens from the browser using the public (anon) key
(`utils/anonClient.js`), so the anon role needs permission to insert, select and
update this table. Configure Row Level Security to allow exactly that and nothing
more. Keep the table's data limited to what you see above — do not store
anything sensitive.

> A sample database dump is included in `backup/` for reference.

## Environment variables

Create a `.env.local` file in the project root:

```bash
NEXT_PUBLIC_SUPABASE_URL=your-supabase-project-url
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-supabase-anon-key
```

Both are the public Supabase values (safe to expose to the browser). These feed
both the SSR auth client (`utils/supabase/`) and the anon tracking client
(`utils/anonClient.js`).

## Clone and run locally

1. Create a Supabase project [via the dashboard](https://database.new) and run
   the table SQL above.

2. Install dependencies:

   ```bash
   npm install
   ```

3. Add your `.env.local` (see above).

4. Run the dev server:

   ```bash
   npm run dev
   ```

   The app runs on [localhost:3000](http://localhost:3000/).

5. Test the tracking flow locally by visiting:

   ```
   http://localhost:3000/test?template_id=1&email=you@example.com
   ```

   then check the `phishing_test` table in Supabase for the recorded click.

## Build & deploy

```bash
npm run build   # production build + type check
npm run start   # serve the production build
```

Deploys cleanly to [Vercel](https://vercel.com) — add the two environment
variables above in the Vercel project settings. The production link used in
campaign emails is served from your Vercel deployment (e.g.
`https://rila-notifications.vercel.app`).

## Project structure

| Path                      | Purpose                                                     |
| ------------------------- | ---------------------------------------------------------- |
| `app/test/page.tsx`       | Landing page that records the click and shows the lesson.  |
| `components/cyber.tsx`    | The security-awareness explainer shown after a click.      |
| `utils/anonClient.js`     | Browser Supabase client used to write click data.          |
| `utils/supabase/`         | SSR Supabase clients (server, middleware) for auth.        |
| `backup/`                 | Sample database dump.                                       |

## Notes

- `next` and the Supabase packages are pinned to `latest` in `package.json`.
  Consider pinning exact versions so an upstream update can't break the build.
- Next.js 16 deprecates the `middleware.ts` convention in favour of `proxy`.
  You can migrate with `npx @next/codemod@canary middleware-to-proxy .`.
